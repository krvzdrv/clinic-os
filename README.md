# clinic-os — демо клинической системы

Это **демо**, а не готовая медицинская информационная система для клиники.

Система помогает врачу вести пациента по клиническому протоколу: **подсказывает**, что сделать дальше, и **проверяет**, не расходится ли назначение с протоколом. Всё видно прямо в карточке пациента — без логина, по одной ссылке.

**Попробовать:** [открыть демо](https://clinic-os-gtwp.onrender.com/demo)

**Код:** [github.com/krvzdrv/clinic-os](https://github.com/krvzdrv/clinic-os)

---

## Что показывает демо

1. Врач открывает карту пациента.
2. Ставит диагноз из справочника (например, внебольничная пневмония).
3. Система подключает протокол и показывает:
   - что ожидается дальше по протоколу;
   - что уже сделано не так или ещё не сделано;
   - предупреждение, если лекарство не подходит (можно подтвердить с причиной или отменить).

Есть и дашборд для руководства: сколько пациентов ведётся по протоколу и где есть зазоры.

Сейчас в демо два протокола Минздрава РБ:

- **Внебольничная пневмония у взрослых** — КП №768
- **Железодефицитная анемия** — КП №23

## Как это устроено (просто)

| Часть | Где | Зачем |
|---|---|---|
| Код | GitHub | Исходники приложения |
| Сервер | [Render](https://render.com) | Крутит сайт по публичной ссылке |
| База данных | [Supabase](https://supabase.com) (Postgres) | Хранит пациентов, приёмы, диагнозы, назначения и данные для проверки протоколов |

Схема такая: **код в репозитории → приложение на Render → данные в Supabase**.  
После обновления кода сервер пересобирается; новые данные из форм сразу попадают в облачную базу.

Локальная база на ноутбуке — только для разработки. Демо смотрят **по ссылке в облаке**.

---

## Почему не использовали RAG

Для этой демки RAG избыточен.

У нас мало протоколов и небольшой набор вариантов выбора (диагноз, признаки, препараты по правилам). Ожидания можно задать явно: факты пациента сравниваются с правилами протокола (пороги, коды, допустимые лекарства). Так проверка прозрачная и предсказуемая.

RAG нужен, когда протоколов и документов много и нельзя всё жёстко описать правилами: система ищет подходящий фрагмент в большой базе текстов. При небольшом объёме данных поиск по текстам только усложняет систему и даёт риск «угадывания» вместо точной сверки.

## Что можно сделать в интерфейсе

1. **Демо** (`/demo`) — сразу открыть карточку демо-пациента.
2. **Список пациентов** — общий обзор и метрика соответствия протоколу.
3. **Новый пациент** — ФИО, пол, дата рождения.
4. **Карта пациента** — жалобы, анамнез, осмотр, анализы, диагноз, назначения; подсказки и проверки протокола сверху.
5. **Экспорт CSV** — таблица для отчётов.

## Запуск у себя на компьютере (по желанию)

Нужны Python 3 и зависимости из `requirements.txt`:

```bash
pip3 install -r requirements.txt
python3 app.py
```

Откройте в браузере: http://127.0.0.1:5566

Без облачной базы приложение использует локальный файл `clinic.db`.  
Как выложить демо в интернет — кратко в [`docs/deployment.md`](docs/deployment.md) (сейчас демо живёт на Render + Supabase).
