# Конспект: фундаментальные концепции клинической ИТ

Краткий конспект технологий и подходов, на которых построена архитектура.
Подробное объяснение — в `clinical_arch_guide.pdf` (на рабочем столе).

## 1. Domain-Driven Design (DDD)

**Eric Evans, 2003.** Метод проектирования сложных предметных областей.

- **Bounded Context** — ограниченный контекст: границы, внутри которых
  термины имеют один смысл. «Эпизод» для врача — приём, для бухгалтерии —
  счёт, для страховой — страховой случай. Разные контексты — разные модели.
- **Ubiquitous Language** — единый язык: разработчики и врачи используют
  одни термины. Не «сущность с полем blood_pressure», а «измерение АД».
- **Anti-Corruption Layer** — слой защиты от загрязнения: переводчик между
  контекстами, чтобы модель одного не портила модель другого.

**Зачем для клиники:** разделяет «клиническую карту» (Condition, Observation)
и «биллинг» (счёт, страховка). Они живут по разным правилам, но обмениваются
данными через ACL.

## 2. CDS Hooks (HL7)

**cds-hooks.org.** Стандарт клинической поддержки решений в точке помощи.

- **Hook** — событие в МИС, когда вызывается CDS-сервис:
  - `patient-view` — врач открыл карту;
  - `order-select` — врач выбирает назначение;
  - `order-sign` — врач подписывает назначение.
- **Card** — карточка-ответ от сервиса:
  - `info` — информация (синяя);
  - `suggestion` — рекомендация (жёлтая, с кнопкой действия);
  - `hard-stop` — блокировка (красная, требует подтверждения).
- **Alert fatigue** — усталость от алертов. Решение: мало карточек,
  только релевантные. В нашем демо — 4 типа, не больше.

**Как работает:** МИС → POST JSON на CDS-сервис → сервис прогоняет правила →
возвращает карточки → МИС показывает врачу.

## 3. Clinical Quality Language (CQL)

**HL7 стандарт.** Язык для записи клинических правил и метрик.

- **Single source of truth:** одни правила для подсказок (prospective,
  контекст Patient) и для метрик (retrospective, контекст Population).
- **Структура:** `Library` → `Parameter` → `Context` → `Define` → `Retrieve` → `Expression`.
- **Два режима:**
  - **Prospective** — «что сделать сейчас»: для подсказки врачу.
  - **Retrospective** — «что было»: для метрики качества за период.

**В нашем MVP:** CQL заменён Python-функциями (читаемее, без Java).
Логика та же: `has_hypertension()` → `last_bp()` → `uncontrolled_bp()`.

## 4. CPG-on-FHIR (Clinical Practice Guidelines on FHIR)

**HL7 implementation guide.** Оцифрованные клинические рекомендации.

- **PlanDefinition** — шаблон протокола (этапы, условия, действия).
- **ActivityDefinition** — конкретное действие (назначить препарат, измерить АД).
- **Questionnaire** — опросник (симптомы, анамнез).
- **Measure** — метрика качества (доля контроля АД).
- **Library** — CQL-правила для протокола.
- **CarePlan** — индивидуальный план для пациента (instance из шаблона).

**Принцип:** `PlanDefinition` (шаблон) → `CarePlan` (instance для пациента).
Протокол — один, планов — много (по числу пациентов).

**В нашем MVP:** CPG-on-FHIR заменён state machine в таблице (6 этапов).
Достаточно для одного протокола. Миграция на CPG — при появлении 2+ протоколов.

## 5. HAPI FHIR

**Open-source FHIR-сервер на Java.** Репозиторий данных, совместимый со стандартом HL7 FHIR.

- REST API: `/Patient`, `/Observation`, `/Condition` и т.д.
- Поддержка FHIR R4.
- PostgreSQL под капотом.

**В нашем MVP:** заменён SQLite + `fhir_store.py`. Модель FHIR-подобная
(те же сущности, те же поля), но без REST API и Java. Миграция —
заменить `fhir_store.py` на HTTP-клиент к HAPI FHIR, правила не меняются.

## 6. Peleg — классика представления клинических алгоритмов

**Mor Peleg, University of Haifa.** Исследователь формализмов клинических алгоритмов.

- **Arden Syntax** — правило «IF condition THEN action» (MLM-модули).
  Первый стандарт CDS, 1991. Жив в виде концепции.
- **GLIF** — Guideline Interchange Format, графовый формат.
- **PROforma** — компоненты: action, decision, plan, enquiry.
- **Принципы живы:** разделение «что решить» (decision) и «что сделать» (action),
  явные условия, граф переходов, исполнимость машиной.

**Связь с CPG-on-FHIR:** CPG-on-FHIR — современная реализация тех же принципов
на базе FHIR. Peleg показала, что клинический алгоритм — это граф с решениями
и действиями, а не просто текст. CPG-on-FHIR кодирует этот граф в PlanDefinition.

## 7. Open-source решения (что доступно)

| Решение | Что | Доступно? |
|---|---|---|
| HAPI FHIR | FHIR-сервер (Java) | да, но тяжело для маленькой клиники |
| CQFramework | CQL-движок + CDS Hooks сервис | да, но нужен Java + CQL |
| OpenMRS | МИС для развивающихся стран | да, но тяжёлый |
| OpenEMR | МИС с базовым CDS (PHP) | да, проще, но CDS примитивный |
| OpenL Tablets | правила в Excel-таблицах | да, интересно для нетехнических |
| Drools | rule engine (Java) | да, но enterprise-уровень |
| NextGen Connect (Mirth) | интеграционный движок | да, для связи систем |
| Snowstorm | SNOMED CT terminology server | да, для терминологий |
| EhrBase | openEHR-сервер | да, альтернатива FHIR |

**Наш выбор:** собственный MVP на Flask + SQLite. Не потому что лучше, а потому что
поддерживаемо одним человеком и даёт нужный эффект. При росте — миграция на
HAPI FHIR + CQL Engine без переписывания правил.
