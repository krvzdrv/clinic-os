# Гармошки не закрываются и не прыгают

Правило для всего приёма (Жалоба → Лечение): после действий с данными
`<details class="fstep">` **не закрываются** и страница **не прыгает**.

## Принцип

После первой загрузки открытость гармошки — состояние браузера (`details.open`).
Его меняет только клик пользователя. Клинический AJAX **не делает** `location.reload()`.

Сервер после записи:

1. пересчитывает протокол (`_refresh_protocol`);
2. отвечает `{ ok: true, soft_refresh: true }` (и опционально `chip_html`).

Клиент (`templates/patient.html`):

1. при необходимости вставляет `chip_html`;
2. вызывает `_softRefreshUi()` — подтягивает HTML страницы и **точечно** меняет
   `#now-action`, списки `#chips-*` / `#dlist-*`, бейджи в summary;
3. **не пишет** в `details.open`;
4. восстанавливает `scrollY`.

Full `reload: true` — только редкие действия (госпитализация, очистка приёма и т.п.).

## Связанные места

| Слой | Где |
|------|-----|
| Ответ API | `app._json_after_clinical` (`soft_refresh`, не `reload` по умолчанию) |
| Клиент | `_ajaxSubmit`, `_softRefreshUi`, chip-x handler |
| Политика CDS | `docs/processes/CDS_SIGNALING.md` §3 п.4 |

## Не путать с

Старый обходной путь `sessionStorage` (`saveFstepUi`) остаётся страховкой на
редкий full reload — не основной механизм стабильности.
