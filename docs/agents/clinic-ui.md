# Бриф: clinic-ui (спринт 1)

## Роль

Интерфейс врача на карточке пациента: мало кликов, этапы ведения, на виду
**подсказка и проверка** протокола. Язык врача, не программиста.

## North star

Демо ≈ 3/10 по «подсказка + проверка». Спринт 1 поднимает верх карточки и
минимальную группировку этапов. Не лепилово полей и не полный редизайн всего UI.

## Ветка

`agent/clinic-ui/sprint1-verdict-panel`

## Можно трогать

- `templates/**` (фокус: `patient.html`; при необходимости стили в том же файле)
- `static/**` если появится
- **узкие** правки `app.py` **только** если architect явно разрешил в merge
  (передача `verdict` в шаблон). По умолчанию: ждать merge protocol + правку
  architect, либо работать от мока/уже переданного `cap` с адаптером в шаблоне
  минимально — предпочтительно ждать `verdict` из `verdict_for_ui`.

## Нельзя трогать

- `protocol_*.py`, `protocol_verdict.py`, `rules_engine.py`
- `docs/protocols/**`
- `schema.sql`, `db.py`, `fhir_store.py`, `tools/**`

## Зависимость

Стартовать после (или параллельно с осторожностью), когда готов контракт
[`verdict-contract.md`](verdict-contract.md). Если `verdict_for_ui` ещё нет —
верстать блок под поля контракта; подключение к `app.py` — merge architect.

## Задачи спринта 1

1. **Верх карточки** — блок «Сейчас по протоколу»:
   - заголовок протокола (`protocol_title`);
   - итог (`headline`) + главная подсказка (`next_step`);
   - ожидаемая терапия (`expected_therapy.title` / `detail`) **без ATC**;
   - список проверок (`checks`) — problem отдельно от info.
2. Убрать из видимого вердикта: ATC, LOINC, gap-коды, сырой JSON.
3. Минимальная группировка этапов (не раздувать остальные секции):
   - Осмотр
   - Диагноз
   - Лечение  
   Остальное не рефакторить глубоко в этом спринте.
4. Осмотр: выбран показатель → ввод только числа (единица из словаря/подписи, не отдельное поле размерности).
5. Назначение: связанные препарат → доза / кратность / маршрут / срок (как уже частично есть — усилить связность, не ломать).

## Критерий готовности (DoD)

- [ ] На карточке первым визуально идёт блок подсказки/проверки
- [ ] Нет ATC/кодов gap в блоке вердикта
- [ ] Этапы Осмотр / Диагноз / Лечение читаются как группы, не как свалка таблиц (порядок = UI_PROCESS_MAP)
- [ ] Единицу измерения при выборе показателя не спрашиваем отдельным полем
- [ ] Краткий отчёт + скрин/описание что увидит гость по ссылке

## Запреты

- Не коммитить без спроса
- Не менять логику `evaluate_cap` / YAML
- Не предлагать «значение + размерность» для уже выбранного показателя
- Не полный редизайн дашборда / всех форм
- Не тёмный «AI-purple» редизайн ради красоты — чистый рабочий UI врача
