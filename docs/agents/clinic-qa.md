# Бриф: clinic-qa (спринт 1)

## Роль

Проверка, что демо по облачной ссылке показывает подсказку и проверку протокола.
Сценарии и сиды под взрослых (КП №768); чеклист ручного демо.

## North star

Гость открыл ссылку → выбрал пациента с отклонением → видит понятную проверку и
что сделать дальше. Если тест падает из‑за бага логики — эскалация architect,
не «подкручивать» protocol/ui вслепую.

## Ветка

`agent/clinic-qa/sprint1-demo-patients`

## Можно трогать

- `tools/scenarios.py`, `tools/e2e_test.py`, `tools/test_*.py`
- `tools/seed_ten.py`, `_seed_data.py` — **только** по явному разрешению в ТЗ
  (в спринте 1 — разрешено для 2–3 демо-пациентов A/B/C)
- новый `docs/agents/DEMO_CHECKLIST.md` (чеклист ручного демо)

## Нельзя трогать

- `protocol_cap.py`, `protocol_rules.py`, `protocol_verdict.py`, YAML правил
- `templates/**` (кроме согласования ожиданий текстов с ui)
- `schema.sql`, `db.py`, `fhir_store.py` (кроме вызовов API store в сидах)

## Задачи спринта 1

1. Три демо-пациента (имена/метки понятные на дашборде):
   - **A** — ведение по протоколу (ok / соответствует)
   - **B** — неверная АБТ (видно problem + next_step)
   - **C** — тяжёлая амбулаторно / без АБТ (госпитализация / нет АБТ)
2. Сид пишет в БД, куда указывает `DATABASE_URL` (облако для демо).
3. `tools/scenarios.py` остаётся зелёным (взрослые ожидания).
4. Чеклист ручного демо в `docs/agents/DEMO_CHECKLIST.md`:
   - открыл URL → пациент B → видит отклонение языком врача → рекомендацию без ATC.

## Критерий готовности (DoD)

- [ ] Пациенты A/B/C воспроизводимо создаются сидом
- [ ] `python3 tools/scenarios.py` → 0 failed
- [ ] Чеклист DEMO_CHECKLIST заполнен шагами
- [ ] Краткий отчёт: как засеять облако, кого открыть гостю

## Запреты

- Не коммитить без спроса
- Не менять прод-логику «чтобы тест прошёл»
- Не оставлять устаревшие дозы/возраст в сидах (только взрослые, КП №768)
- Не требовать localhost как среду демо
